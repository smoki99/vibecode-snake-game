# AGENT.md — how to work in this repo

## Do not overthink.

Act, verify, move on. If a fix is obviously right, make it. Do not enumerate five options, do not
write a design doc for a two-line change, do not re-plan work that is already planned in
`tasks/todo.md`. Aim for the shortest path that is still *correct*, and let the test suite be the
argument.

Concrete rules that follow from that:

- **Fix root causes, then prove it with a command.** "It should work" is not a result; the output of
  `npm run test:browser` is.
- **One change, one verification.** Run the narrowest test that covers the change, not the whole
  suite, until you're ready to commit.
- **Prefer the mechanical fix.** Selector wrong → use the real id. Key name wrong → use the real
  key. Do not redesign the API to suit the test unless the test is right and the API is wrong.
- **Read before you write.** Check the actual signatures (`readState`, `OVERLAY_COPY`, the DOM ids in
  `index.html`) instead of guessing, then edit with exact anchors on the first try.
- **Small commits.** Each commit leaves the suite green or moves one named failure to green.
- **Don't gold-plate.** No new abstractions, config, or "while I'm here" refactors outside the task.
  If it's out of scope, note it and stop.
- **Ask only when blocked.** Missing credentials and destructive choices are worth asking about;
  ambiguity with a sane default is not — pick the default and say so in the commit message.
- **Time-box research.** If you've spent two tool calls on context and none on the change, make the
  change.

## When "don't overthink" does NOT apply

Quality gates stay non-negotiable, and these are exactly where care pays off:

- Never weaken, skip or delete an assertion to get green. A test that can't fail is worse than a red
  one (this repo had four of those — see `snakeLength` in `tests/browser/gameplay.spec.mjs`).
- Never fake a result, and never report a check you didn't run.
- Sim rules (`src/sim/`), determinism (`?seed=`), and the network-silence promise are load-bearing.
  Think those through; everything else is cheap to change later.

## Repo map (so you don't have to rediscover it)

| Path | What |
| --- | --- |
| `src/sim/` | pure, DOM-free game rules — unit-tested, no browser needed |
| `src/render/`, `src/ui/` | canvas + DOM layer; exercised by the browser suite only |
| `index.html` | **source of truth for every id/data-attribute tests reference** |
| `tests/helpers/browser.mjs` | Playwright scaffolding: `openPage`, `readState`, `press`, `armKeys`, `eatApples`, `pumpUntilInPage` |
| `tools/serve.mjs` | static server on :8080 (the preview); `cloudflared tunnel --url http://localhost:8080` for a public URL |

## Commands

```bash
npm test            # headless: unit + assets + build  (fast, no browser)
npm run test:browser # Playwright; needs the server on :8080 and chromium
npm run test:all    # everything
npm run check       # sprite --check + build + both suites — this is the gate
node tools/serve.mjs --port 8080   # serve the app (log to /workspace/.app.log when backgrounded)
```

## Environment gotchas (real, learned the expensive way)

- **The sandbox CPU is heavily oversubscribed**: wall-clock time inside this container runs ~30×
  slower than real time. Long foreground `sleep`/curl calls hit the harness timeout — run work
  detached (`setsid --fork … &`) writing to a file, then poll the file.
- Browser tests are flaky for environment reasons, not game reasons: first input event into cold
  Chromium can take tens of seconds, and a wedged renderer returns `null` from `evaluate`. Helpers
  already absorb this (`warmUp`, `press`, `armKeys`). **Always read the failure message before
  believing "flaky".** `undefined === undefined` passing is a bug in the test, not flakiness.
- Playwright is installed globally at `/opt/shared-tooling/npm`; import it via
  `tools/load-playwright.mjs`, which falls back to that absolute path.
- Cloudflare quick tunnels get a **random URL on every restart** and are ephemeral — update
  `README.md`/`SUMMARY.md` with the new URL, or prefer a durable deploy if credentials ever appear.

## Conventions

- ES modules everywhere, `"type": "module"`; no build step required to run the source.
- Tests import the shipped modules directly — never a copy of the logic under test.
- Icons are hand-authored 24×24 stroke SVGs in `assets/icons/` (source of truth);
  `assets/icons.svg` is generated by `tools/sprite.mjs`, and `--check` fails on drift.
- Commit messages: imperative, say *why*, mention the test that now passes.
